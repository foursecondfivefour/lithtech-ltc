# Roadmap — порт LTC

Инструмент: `tools/LTC` из LithTech — сжатие/распаковка LTA (LZSS, окно 4096,
look-ahead 17, собственный битовый поток). Подробный разбор — `ANALYSIS-4.md`.

Метод: **рекон → эталон → порт 1:1 → расхождения только с записанным обоснованием**.
Оракул — `ref-build/build/ltc`, собранный из оригинальных исходников под Linux.

## Статус

| | милстоун | гейт | статус |
|---|---|---|---|
| **M0** | эталон + корпус + золотые файлы + детерминизм | `scripts/m0_gate.sh` | **PASS** |
| **M1** | CLI 1:1 + битовый слой + запись потока «без сжатия» | `scripts/m1_gate.sh` | **PASS** |
| **M2** | `CLZSSWindow` 1:1 → **сжатие** байт в байт | `scripts/m2_gate.sh` | **PASS** |
| **M3** | декодер, `-view`, round-trip на корпусе | `scripts/m3_gate.sh` | **PASS** |
| **M4** | инварианты, второй компилятор, документация, «без предупреждений» | `scripts/m4_gate.sh` | — |

## M0 — сделано (2026-11-06)

Состав:

* `ref-build/` — эталонный бинарник, собирается **с нуля** одной командой
  (`ref-build/build.sh`, 19 TU, ~6 с); две механические правки под gcc и четыре шима
  описаны в `ref-build/PATCHES.md`.
* `golden/make_corpus.py` — 56 fixture'ов, детерминированы seed'ами, 1.03 МБ.
  Покрытие: пустой файл, 1/2/3 байта, длины 15…33 вокруг look-ahead 17, границы окна
  4095/4096/4097/4098, периоды 1…4095, ГСЧ 100…50000 байт, алфавиты 2/4/8/16,
  псевдо-LTA текст, исходник C++, английский и UTF-8 (кириллица), нули 64 КБ,
  редкий шум, смешанный файл 256 КБ.
* `golden/expected/` + `manifest.txt` + `expected.sha256` — 56 золотых `.ltc`
  (459 КБ), каждый с хэшами входа и выхода.
* `docs/decode.py` — независимый декодер, написанный только по чтению исходников.

Измерено на полном корпусе:

| проверка | результат |
|---|---|
| round-trip `fixture → .ltc → fixture` эталоном | 56/56 байт в байт |
| те же `.ltc` при повторной сборке эталоном | 56/56 совпали |
| независимый декодер `docs/decode.py` | 56/56 восстановил fixture |
| детерминизм (2 прогона) | 56/56 идентичны |
| `-verbose` не влияет на вывод | 56/56 идентичны |
| двойное сжатие `.ltc`-как-данных | обратимо (17 493 → 19 458 → 17 493) |
| сборка эталона дважды подряд | один и тот же sha256 бинарника |

Сжатие корпуса (для будущих регрессий): случайные данные **расширяются** (~+12 %,
литерал стоит 9 бит), текст LTA-подобный сжимается в 3.9×, нули 64 КБ → 8 216 байт.

Запуск: `scripts/m0_gate.sh` (полный, с пересборкой эталона) или
`scripts/m0_gate.sh --no-build` (3 с).

## M1 — сделано (2026-11-06)

Порт в `port/` (C++20, CMake, без внешних зависимостей):

| модуль | что |
|---|---|
| `command_line.{h,cpp}` | порт `CCommandLineParser` (склейка аргументов через пробел, split по пробельным, лимиты 64/128, перенос лишних параметров в глобальные) |
| `paths.{h,cpp}` | `is_file_compressed` и построение имени выхода (Q3, Q5) |
| `bits.h` | `BitWriter` (биты от младшего, поля старшим вперёд, потеря хвоста — Q2) и `BitReader` (бит при EOF = 0 — Q10) |
| `file.{h,cpp}` | побайтовые `rb`/`wb`-потоки, семантика `CLTAFileBuffer` |
| `compressed_stream.{h,cpp}` | писатель `.ltc` (версия + литеральные токены + EOS) и чтение заголовка |
| `app.{h,cpp}` | `main.cpp` 1:1: порядок проверок, тексты, коды возврата, `-view`, имена |
| `tests/test_m1.cpp` | 345 проверок без внешних зависимостей |

Сознательное ограничение этапа: **LZSS ещё нет** (M2) и **декодера нет** (M3) — поэтому

* запись даёт валидный, но несжатый поток (все токены литеральные, 9 бит на байт);
* чтение `.ltc` возвращает код **2** с сообщением в stderr (в дифференциальном гейте такие
  сценарии помечены SKIP, а не OK).

Гейт `scripts/m1_gate.sh` — 5 шагов, 13 с:

| проверка | результат |
|---|---|
| сборка порта `-Wall -Wextra -Wpedantic -Werror` | 0 предупреждений |
| юнит-тесты | 345 проверок, 0 падений |
| дифференциальный CLI-гейт (44 сценария) | 44 OK, 0 FAIL, 5 SKIP |
| `ref(port(x)) == x` на всём корпусе | 56/56 |
| байт-в-байт с эталоном | 13/56 (там, где эталон тоже пишет одни литералы) |
| размеры (ожидаемый разрыв) | текст 68 297 Б: эталон 17 493 → порт 76 840; пустой/1/2 Б — идентичны |

Решения, принятые на этом этапе (подробно — `porting-notes.md`): Q4 — затирание `.lta`
повторяем; Q5 — имя выхода в `std::string` без лимита 256 (UB устранён); Q10 — бит при EOF
равен 0; Q11–Q13 — квирки разбора аргументов и «сжатость выхода = отрицание сжатости входа»
повторяются.

## M2 — сделано (2026-11-06)

`port/src/lzss_window.cpp` — построчный порт `CLZSSWindow`: окно 4096 + ghost-буфер 17,
дерево `m_Tree[4097]` с `ROOT_NODE = 4096` и `NULL_NODE = 0`, `add_node` с удвоенным
сравнением 17 байт и заменой узла при точном совпадении, `delete_node`/`collapse_node`/
`replace_node`, перенос кандидата `m_MatchPos/m_MatchLen` между вызовами, `BREAK_EVEN_POINT`,
`flush_look_ahead` с дописыванием EOS.

**Результат: побайтовый паритет получен с первой сборки, без единой отладки расхождений.**

Гейт `scripts/m2_gate.sh` — 8 шагов, 35 с:

| проверка | результат |
|---|---|
| 56 золотых `.ltc` против эталона | **56/56 байт в байт** |
| фазз-сверка (по умолчанию 300 случаев, 10 режимов) | 0 расхождений; `--fuzz 1500` — тоже 0 |
| файлы 1 МБ (монотонный, случайный, текст, период 17) | все совпадают |
| инварианты формата (`golden/dump_tokens.py --assert`) | 56/56, нарушений 0 |
| ASan/UBSan на корпусе + 100 фазз-случаях | ни одного отчёта |
| регрессия M0 и M1 | PASS |
| производительность | порт ~3× быстрее эталонной сборки (1 МБ: 0.03 с против 0.15 с) |

Наблюдения по структуре потока (из дампера): текст LTA-подобный 68 297 Б → 225 литералов
и 8 110 span'ов (94 % токенов — ссылки), нули 64 КБ → 18 литералов и 3 854 span'а.

## M3 — сделано (2026-11-06)

`port/src/lzss_decoder.cpp` — порт `CLTACompressedFile::ReadByte`: окно 4096, позиция
записи с 1, побайтовое копирование span'а с перекрытием, `m_SpanLen/m_SpanPos` как
состояние между вызовами, EOS = span с offset 0 (длина при этом не читается).

Гейт `scripts/m3_gate.sh` — 8 шагов, 37 с:

| проверка | результат |
|---|---|
| декодирование 56 эталонных `.ltc` | 56/56 = исходные файлы |
| `-view` на сжатых файлах | 56/56 = содержимое исходника |
| round-trip силами одного порта | 56/56 байт в байт |
| CLI-гейт против эталона | **51 OK, 0 FAIL, 0 SKIP** (декодирующие сценарии больше не пропускаются) |
| свип по обрезкам (`truncation_sweep.py`, 3 файла, шаг 1) | 176 расхождений — **все** внутри зоны неопределённости эталона, 0 вне её |
| ASan/UBSan на путях декодирования | 56 распаковок + 56 `-view` + юнит-тесты — чисто |
| регрессия M0/M1/M2 | PASS |

**Найденное ограничение паритета (и почему это не баг порта).** Если поток `.ltc`
оборван *посреди токена*, эталон читает недостающие биты из неинициализированной
переменной (`CLTABitFile::GetBit` при конце файла возвращает `false` и не трогает
выходной параметр). Воспроизвести это нельзя в принципе — результат зависит от
содержимого стека. Порт фиксирует правило «бит за концом файла = 0» (Q10), поэтому
на таких файлах выдаёт корректный по формату (детерминированный) результат.
`scripts/truncation_sweep.py` проверяет границу зоны: для каждого префикса потока
сравниваются выходы обеих реализаций и отдельно считается, попала ли обрезка ровно
на границу токена. Утверждение гейта: **вне зоны неопределённости расхождений нет**.
В CLI-гейте такие входы (сценарий `junk_ltc`) помечены режимом `codes`: сравниваются
коды возврата и потоки, содержимое — нет.

## M4 — инварианты и документация

Юнит-тесты: порядок бит, границы span 2..17, потеря хвоста, EOS = 17 бит,
окно 4096 (в т.ч. ровно 4096 и 4097), offset 0. Сборка clang + gcc, «без
предупреждений» для нового кода, README/porting-notes в финальном виде.
