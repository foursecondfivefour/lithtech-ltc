# Porting notes — журнал решений

Каждое отклонение порта от эталона фиксируется здесь: что, почему, чем проверено.
Если отклонение не записано — его не существует.

Легенда статусов: **открыт** (решение не принято) · **решено** (принято, ждёт реализации) ·
**реализовано** (есть код + тест).

---

## Квирки эталона (обязательны к повторению)

### Q1. `-verbose` — мёртвый флаг — **реализовано** (M1)
Флаг принимается, нигде не читается, вывода не добавляет (замерено: 0 байт stdout,
файл побайтово тот же). Порт повторяет: опция распознаётся, значение игнорируется.
Тест: `m0_gate.sh` шаг 5 (эталон) → `cli_parity.sh` (порт).

### Q2. Последний неполный байт потока теряется — **реализовано** (M1), подтверждено (M2)
`CLTABitFile::Close()` не флашит `m_nCurrData`, поэтому 1…7 хвостовых бит исчезают.
Видимый результат: пустой вход → 6 байт (32 версии + 17 EOS = 49 бит), 1 байт → 7,
2 байта → 8. Порт обязан повторить, «правильный» flush запрещён.
Тест: `golden/expected/{empty,one_A,two_ab}.ltc` + юнит-тест на `Close()`.
Побочный эффект, видимый дампером: EOS часто записан не целиком (`pad` = 1…16 бит) —
декодер «дорисовывает» недостающие биты нулями (Q10) и потому читает его как EOS.

### Q3. Сжатость входа — только по расширению — **реализовано** (M1)
`CLTAUtil::IsFileCompressed()` смотрит на `.ltc` без учёта регистра и ничего больше.
Из этого следует неочевидное: переименование меняет смысл файла, а `-out` на тип входа
не влияет. `.ltc` с чужим содержимым падает на проверке версии:
`Error: Unable to open the file X`, код 1.
Тест: `cli_parity.sh` (fake.ltc), шаг 6 гейта M0 (вложенное сжатие через `.bin`).

### Q4. Распаковка без `-out` затирает одноимённый `.lta` — **решено: повторяем** (M1)
`ltc scene.ltc` открывает `scene.lta` на `wb` и уничтожает его, если он существовал.
Решение: повторять, стderr не расширять (любое предупреждение сломало бы паритет потоков).
Порт открывает выход именно так (`RawWriter` → `fopen("wb")`), поведение зафиксировано
сценарием `decompress_out` в `scripts/cli_parity.sh` (включается на M3) и в README.

### Q5. `strcpy` без проверки длины — **решено** (M1)
`main.cpp` формирует имя выхода через `strcpy` в `char[_MAX_PATH]` (`_MAX_PATH == 256`
под `__LINUX` в `ltbasedefs.h`). Классическое переполнение стека. Варианты:
(а) воспроизвести как есть; (б) реализовать через `std::string` с обрезкой по 255;
(в) реализовать безопасно и вернуть ошибку на слишком длинном пути.
Решение: **(б) без ограничения длины** — порт хранит имя выхода в `std::string` и не обрезает
его. Единственное отличие от оригинала: на путях длиннее 255 символов оригинал имеет
неопределённое поведение (переполнение стека), порт работает корректно. Никакие другие пути
поведение не меняют; проверено юнит-тестом на 300-символьном пути.

### Q6. Окно декодера не обнуляется при открытии — **решено: обнуляем** (M3)
`m_DecWnd` заполняется только записанными байтами, `m_nDecWndPos` начинается с 1;
span, ссылающийся на незаполненную область, вернёт мусор (в оригинале — со стека).
На корректных потоках недостижимо: компрессор ссылается только назад, на уже
записанные байты. Решение: порт **обнуляет окно** — это единственное место, где порт
определённее оригинала.

Цена решения измерена: на потоке, где span'ы смотрят в незаписанную часть окна
(`junk.ltc` в CLI-гейте), эталон выдаёт 63 байта «мусора со стека», порт — 46 байт,
ровно столько, сколько даёт разбор токенов. Расхождение задокументировано и помечено
в гейте режимом `codes` (сравниваются коды и потоки, не содержимое).

### Q7. `CLTAHuffmanTree` — мёртвый код — **решено** (порт его не содержит)
457 строк не используются ни одним вызывающим (проверено grep по `libs/` и `tools/`).
Порт не реализует; заголовок `ltacompressedfile.h` обещает «adaptive huffman», но формат
— LZSS. В README это сказано явно, чтобы не искали Huffman.

### Q8. `offset == 0` зарезервирован под EOS — **решено: коллизия невозможна** (M2)
Риск из ANALYSIS-4 §6.12 (компрессор найдёт совпадение в позиции окна 0 и запишет span,
который декодер прочтёт как конец файла) **конструктивно исключён**: `AddNode` первой же
строкой делает `if (nWindowNode == NULL_NODE) return;`, а `NULL_NODE == 0`, поэтому позиция
окна 0 никогда не попадает в дерево и не может стать `mMatchPos` (он равен `curr_node`,
а тот всегда ≠ 0). Позиция 0 остаётся только «данными», которые копируются внутри span'ов.
Проверка: `golden/dump_tokens.py --assert` на всём корпусе — ровно один span с offset 0
(последний, EOS), других нет.

### Q14. Окно инициализируется нулями — отклонение только для детерминизма (M2)
Оригинал `CLZSSWindow::Init()` окно не обнуляет. Разбор (`ANALYSIS-4.md` §5) показывает,
что читаются всегда только записанные байты: сравнение идёт вперёд от уже вставленного узла
(все байты записаны) и от текущей позиции (look-ahead заполнен), а ghost-буфер пишется
раньше, чем до него дотянется сравнение. Тем не менее порт обнуляет окно — это убирает
зависимость от содержимого стека под санитайзерами. Побайтовый паритет на 56 файлах,
1 500 фазз-случаях и файлах по 1 МБ подтверждает, что на вывод это не влияет.

### Q10. Чтение бита за концом файла — **решено** (M1)
`CLTABitFile::GetBit` при EOF возвращает `false` и не присваивает выходной параметр; цикл
чтения версии это возвращаемое значение игнорирует и читает неинициализированную переменную.
Решение порта: **бит при EOF = 0**. Это ровно то поведение, которое наблюдается у эталона
(0…8 нулевых байт → версия валидна, любой ненулевой бит → «Unable to open the file»),
и оно детерминировано. Зафиксировано в `ltc/bits.h` (BitReader) и проверено сценариями
`corrupt_version`, `empty_ltc`, `junk_ltc`.

### Q10a. Обрезка посреди токена — зона неопределённости эталона (M3)
`GetBit` при конце файла не присваивает выходной параметр, а вызывающий код в циклах
чтения offset/длины/байта игнорирует возвращаемое значение. Значит, если поток
обрывается *внутри* токена, эталон достраивает его из содержимого стека. Правило порта
(«бит за концом файла = 0») даёт детерминированный результат и совпадает с эталоном
всюду, где тот определён — это проверяется `scripts/truncation_sweep.py`: для каждого
префикса потока сравниваются выходы, и утверждение гейта — «расхождения только внутри
зоны». Измерено на трёх файлах (шаг 1 байт): 176 расхождений, все внутри зоны, 0 вне.

### Q11. Опция `-` (пустое имя) — **решено: повторяем** (M1)
`ltc -` даёт справку и `Unknown option: ` — имя опции пустое, и `is_option_set("")` для неё
истинно (strcasecmp с пустой строкой). Порт ведёт себя так же; проверено юнит-тестом и
сценарием `lone_dash`.

### Q12. Порядок проверок CLI — **решено: повторяем** (M1)
`-help` перекрывает даже неизвестные опции; «нужен файл» проверяется раньше, чем «-out без
значения»; `-view` обрабатывается до проверки расширения. Это видно на кодах возврата и
закреплено 44 сценариями `scripts/cli_parity.sh`.

### Q13. Сжатость выхода = отрицание сжатости входа — **решено: повторяем** (M1)
`-out` влияет только на имя файла, но не на формат: `ltc x.lta -out y.lta` пишет сжатые
данные в `.lta`, `ltc x.ltc -out y.ltc` — несжатые в `.ltc`. Режима «копировать как есть» нет.
Порт использует ровно этот флаг; проверено сценариями `compress_to_lta_ext`, `compress_raw`.

### Q9. Псевдослучайность не используется — решено
Ни ГСЧ, ни времени, ни указателей в выводе: сжатие чисто детерминировано (проверено
двумя прогонами на 56 файлах).
